# מערכת מכון משפטי ארץ

ניהול קשרים (CRM), שו"ת, השתלמויות ומעקב מחקר – באתר אחד על GitHub Pages, עם מסד נתונים ב-Firebase.

## הדפים באתר

| קובץ | למי | מה זה |
| --- | --- | --- |
| `index.html` | צוות | מערכת הניהול (כניסה עם Google, רק לכתובות מורשות) |
| `ask.html` | ציבור | טופס "שאל את הרב" |
| `shut.html` | ציבור | מאגר שו"ת (שאלות שפורסמו בעילום שם) |
| `course.html?c=...` | ציבור | דף נחיתה והרשמה להשתלמות – טופס פתוח, בלי חשבון (הקישור בלשונית "פרסום") |
| `my.html` | משתלמים מאושרים | האזור האישי (כניסה עם Google של המייל שנרשמו איתו): לו"ז, זום, הקלטות, חומרי לימוד, נוכחות, הוספה ליומן, משוב, רקע |
| `shop.html` | ציבור | חנות הספרים – הזמנה ותשלום ב-Jgive |
| `unsubscribe.html` | ציבור | הסרה מרשימת התפוצה (הקישור מופיע בכל מייל) |
| `manifest.webmanifest`, `sw.js`, `img/icon-*.png` | – | התקנת המערכת בטלפון כאפליקציה |
| `accessibility.html`, `privacy.html` | ציבור | הצהרת נגישות ומדיניות פרטיות (להשלים את המסומן בצהוב) |
| `js/config.js` | – | פרטי Firebase וקטגוריות ברירת מחדל |
| `firestore.rules` | – | חוקי אבטחה – **להדביק ב-Firebase אחרי כל עדכון שלהם** |
| `mail-scheduler.gs`, `appsscript.json` | – | הסקריפט של המכון: שליחת כל המיילים, תזכורות, משוב, התראות שו"ת, גיבוי וחיבור ל-Jgive (מדביקים ב-Apps Script, לא צריך להעלות לאתר) |

## הקמה (פעם אחת)

1. **פרויקט Firebase**: console.firebase.google.com ← Add project.
2. **מסד נתונים**: Build ← Firestore Database ← Create database ← Production mode ← מיקום `eur3`.
3. **חוקי אבטחה**: לשונית Rules ← מדביקים את כל `firestore.rules` ← Publish.
4. **כניסה עם Google**: Build ← Authentication ← Sign-in method ← Google ← Enable ← Save.
5. **חיבור האתר**: Project settings ← Your apps ← `</>` ← מעתיקים את `firebaseConfig` ל-`js/config.js`.
6. **GitHub Pages**: Settings ← Pages ← Branch: main ← Save.
7. **דומיין מורשה**: Authentication ← Settings ← Authorized domains ← מוסיפים `שם-המשתמש.github.io`.
8. **מנהל ראשון**: Firestore ← Start collection `allowedEmails` ← Document ID = כתובת ה-Gmail שלך באותיות קטנות ← שדה `role` = `admin`, שדה `name` = השם שלך.
9. מכאן מוסיפים את כל הצוות מתוך האתר, בלשונית **משתמשים**.

## תפקידים

| תפקיד | מה רואה ועושה |
| --- | --- |
| מנהל מערכת (`admin`) | הכול, כולל משתמשים, הגדרות ומחיקות |
| רכז הרכזים (`head`) | הכול חוץ מניהול משתמשים: CRM, שו"ת, כל ההשתלמויות, מעקב מחקר, הגדרות |
| צוות (`staff`) | CRM, שו"ת, ייבוא, כל ההשתלמויות |
| רב משיב (`rabbi`) | שו"ת ותקציר על השואל |
| רכז השתלמות (`course_manager`) | רק ההשתלמויות שהוא רשום כרכז שלהן (פרטים, לו"ז, נרשמים, נוכחות, הקלטות, פרסום) + לוח השנה של כולן |
| רכז מחקר (`research_coord`) | הדיווחים החודשיים של כל החוקרים (גם מנהל ורכז הרכזים רואים אותם) |
| חוקר (`researcher`) | רק הדיווח החודשי שלו |

**משתלמים** לא צריכים להיות ברשימת המשתמשים. הם נרשמים בטופס הפתוח, הרכז מאשר, ואז הם נכנסים ל-`my.html` עם חשבון Google של כתובת המייל שאיתה נרשמו. כל אחד רואה רק את ההשתלמויות שאושר אליהן.

## השתלמויות – איך עובדים

**השתלמויות ← + השתלמות חדשה** פותח אשף בשישה צעדים. בכל צעד יש "הקודם / הבא", וצעד שהושלם מסומן ב-✓:
1. **פרטים**: שם, תיאור, מרצים, תאריכים, רכזים, מלגות והקלטות, ו**שדות טופס ההרשמה**: לכל שדה (טלפון, מוסד לימודים, כתובת מגורים, הערות, הסכמה לדיוור) בוחרים חובה / רשות / לא להציג. שם ומייל תמיד חובה.
2. **לו"ז**: מפגש בודד או סדרה שבועית, עם התראה על התנגשות (אותו מרצה או אותו חשבון זום באותו זמן, בכל ההשתלמויות).
3. **דף ההרשמה**: תצוגה מקדימה חיה של הדף כפי שהנרשמים יראו אותו. בתצוגה המקדימה ההרשמה לא נשלחת.
4. **מודעה**: נבנית מתבנית הפלאייר של המכון ומתמלאת אוטומטית: שם ההשתלמות, מספר המפגשים, ימים ושעות, תאריכים (עבריים ולועזיים), רשימת הנושאים והמרצים מהלו"ז, טקסט המלגה, וקוד QR שמוביל לדף ההרשמה. ב**עורך** אפשר לשנות כל טקסט, לגרור, להגדיל ולהקטין כל אלמנט, להחליף צבעים, גופנים ותמונות. אלמנט שמסומן "להציג רק אם יש ערך" (למשל תיבת המלגה) נעלם כשאין לו תוכן. "שמירה" שומרת להשתלמות הזו. מנהל ורכז הרכזים יכולים גם לשמור **כתבנית לכל ההשתלמויות**. "חזרה לעיצוב המקורי של המכון" מחזיר לפלאייר המקורי.
5. **רקעי זום**: רקע לכל מרצה מתבנית רקע הזום של המכון. מתחלפים רק שם המרצה ונושא ההרצאה (הנושא של המפגשים שלו בלו"ז, ואם אין – שם ההשתלמות). אפשר להוריד רקע לכל מרצה, או את כולם בלחיצה אחת. גם המשתלמים מורידים רקע עם השם שלהם מהאזור האישי.
6. **פרסום**: כפתור "פתיחת ההרשמה", קישור לדף ההרשמה, הודעה מוכנה וכפתור "שיתוף בוואטסאפ".

בצעד **פרטים** יש גם שלושה מתגים (כולם דלוקים כברירת מחדל): **תזכורת אוטומטית במייל** כ-24 שעות לפני כל מפגש (עם קישור הזום, הנושא, המרצה וקישור להוספה ליומן), **הוספה ליומן** (Google / אייפון / אאוטלוק, עם תזכורת בטלפון שעה ויום לפני) מהאזור האישי, ו**בקשת משוב** אוטומטית אחרי המפגש האחרון. מפגש בלי קישור זום מסומן "⚠ חסר קישור" בלו"ז ובדף הראשי, והרכז מקבל מייל יום לפני.

אחרי הפרסום עובדים בלשוניות **ניהול**:
- **נרשמים**: ממתינים, מאושרים, נדחו וביטלו. אישור נותן גישה לאזור האישי ומציע לשלוח מייל אישור. אפשר גם הוספה ידנית, **ייבוא מאקסל** (עמודות: שם פרטי, שם משפחה או שם מלא, מייל, טלפון, מוסד לימודים, כתובת, הסכמה לדיוור – בוחרים אם הם נכנסים כמאושרים או כממתינים), עריכה, אישור מלגות, ייצוא לאקסל, "מייל למאושרים" ו"תזכורת למפגש הבא".
- **נוכחות**: למעלה **סימון מהיר** – בוחרים מפגש ומסמנים את הנוכחים ברשימת שמות (או "סימון כולם"). אפשר גם לייבא דוח משתתפים מזום, ולמטה טבלה של כל המפגשים עם ייצוא לאקסל. בזמן המפגש המשתלם רואה באזור האישי כפתור **"אני נוכח/ת במפגש"** – אפשר לסמן רק ביום המפגש, והסימון מופיע אצל הרכז.
- **הקלטות וחומרים**: קישורי יוטיוב לכל מפגש (עם כפתור שמציג או מסתיר אותם), וחומרי לימוד – שורה לכל פריט: `כותרת | קישור` (מעלים ל-Google Drive ומשתפים "כל מי שיש לו את הקישור"). החומרים מופיעים לנרשמים באזור האישי.
- **משוב**: ממוצעי הדירוג (כללי, תוכן, מרצים), אחוז הממליצים, ההערות וייצוא לאקסל.

**לוח שנה**: כל המפגשים מכל ההשתלמויות, עם רשימת התנגשויות לכל חודש. רשימת חשבונות הזום מוגדרת ב**הגדרות**.

## מחקר – דיווח חודשי

- **חוקר**: פעם בחודש כותב **מה עשה והשיג החודש** ו**מה היעד שלו לחודש הבא**. מעל הטופס מוצג היעד שהציב לעצמו בחודש הקודם, כך שבסוף כל חודש הוא רואה מה רצה להשיג מול מה שהשיג. מתחת – כל החודשים הקודמים שלו. בשבוע הראשון של החודש הטופס נפתח אוטומטית על החודש שהסתיים.
- **מנהל, רכז הרכזים ורכז מחקר**: מסך אחד לכל חודש, כל החוקרים זה מתחת לזה: היעד שהציב, מה הושג, והיעד לחודש הבא. למעלה – כמה הגישו ומי עוד לא. אפשר לכתוב הערה לכל חוקר (הוא רואה אותה), לדפדף בין חודשים ולהדפיס או לשמור כ-PDF.

## שאר המערכת

- **ייבוא** (Excel או CSV, גם בקידוד של Excel בעברית). אנשים קיימים מזוהים לפי מייל או טלפון. בוחרים מה הקובץ מכיל:
  - **חלוקת ספרים / מכירת ספרים**: ספר אחד לכל השורות מתוך רשימת ספרי המכון, או עמודה בקובץ (מותאמת אוטומטית לרשימה; כמה ספרים בתא – בפסיק). תאריך החלוקה/הקנייה – מעמודה, או תאריך אחד לכל הקובץ. בקנייה גם סכום.
  - **נרשמים להשתלמות**: השתלמות אחת מהמערכת לכל השורות, או עמודה עם שם ההשתלמות, או השתלמות ישנה שלא במערכת (רק תיעוד). סטטוס – מעמודה (מאושר / ממתין / נדחה / ביטל) או סטטוס אחד לכולם. השתלמות שבמערכת: האנשים נרשמים אליה ממש.
  - **רשימת ספרי המכון** מוגדרת ב**ספרים ← קטלוג וחנות**.
- **חיתוכים**: באנשי קשר, "תנאי היסטוריה" ← שמירה כרשימה ← ייצוא או העתקת מיילים (רק של מאשרי דיוור).
- **שו"ת**: קטגוריות ותגיות אוטומטיות לפי מילות מפתח מוגדרות ב**הגדרות**. התשובה נכתבת בעורך עם מודגש, קו תחתון, כותרת, כותרת משנה ורשימה. "✉ שליחת התשובה לשואל" שולח מייל מעוצב עם השאלה והתשובה (וגם אחרי "שמירה" של שאלה שנענתה המערכת מציעה לשלוח). את נוסח השאלה לפרסום אפשר לערוך – המקור נשמר. "העתקת השאלה והתשובה" מעתיקה עם כותרות "שאלה" ו"תשובה" וכותרות המשנה, להדבקה בוורד או במסמך.
- **שו"ת – התראות** (הגדרות ← התראות שו"ת במייל): מייל לרב על כל שאלה חדשה (לפי קטגוריה, או לרשימת ברירת מחדל), ותזכורת על שאלה שלא נענתה אחרי X ימים. בטופס "שאל את הרב" מוצגות לשואל שאלות דומות מהמאגר לפני שהוא שולח. בכל שאלה במאגר יש "שיתוף בוואטסאפ" ו"העתקת קישור".
- **מיילים מעוצבים**: בכל חלון שליחה אפשר לכתוב שורה שמתחילה ב-`## ` לכותרת, `### ` לכותרת משנה, `**טקסט**` למודגש ו-`__טקסט__` לקו תחתון.
- **דוחות** (מנהל ורכז הרכזים): לכל חודש בשנה – שאלות, זמן מענה, הרשמות, נוכחות, ספרים שחולקו ונמכרו, תרומות ואנשי קשר חדשים; סיכום לכל השתלמות; ייצוא לאקסל והדפסה.
- **יומן שינויים** (משתמשים ← יומן שינויים, רק למנהל מערכת): מחיקות, מיזוגים, הרשאות, ייבוא והגדרות – מי, מה ומתי. אי אפשר לערוך או למחוק אותו.
- **גיבוי**: אוטומטי כל יום ראשון בלילה לתיקייה "גיבוי מערכת משפטי ארץ" ב-Google Drive של חשבון המכון (12 אחרונים נשמרים), ובנוסף כפתור "הורדת גיבוי מלא" בהגדרות.
- **התקנה בטלפון**: בדף הראשי מופיע "📱 התקנה בטלפון". המערכת נפתחת כמו אפליקציה, עם אייקון במסך הבית.

## פרויקטים (מנהל מערכת)

תפריט **פרויקטים** – תמונת מצב של כל הפרויקטים הפתוחים, ברשימה:
- לכל פרויקט: שלב (רעיון / בתכנון / בביצוע / ממתין / הושלם), מצב (🟢 במסלול / 🟡 בסיכון / 🔴 תקוע / ⚪ מושהה), עדיפות, אחראי, תאריך יעד, תגיות, **השלב הבא** (מה, מי ועד מתי), אבני דרך עם פס התקדמות, וקישורים.
- למעלה: כמה פתוחים, כמה תקועים או בסיכון, כמה עברו את היעד, כמה לא עודכנו 14 יום, ומה נופל השבוע. באדום – יעד שעבר, שלב הבא באיחור, או פרויקט שלא עודכן.
- **עדכון מהיר** בתוך כל פרויקט: מה נעשה, מה המצב, מה השלב הבא. כל שינוי נשמר ב**היסטוריית העדכונים** עם תאריך ושם (גם שינוי שלב או סימון אבן דרך נרשם לבד).
- סינון לפי שלב, מצב, אחראי ותגית; מיון לפי יעד, עדיפות, מצב או "עודכן הכי מזמן"; ייצוא לאקסל והדפסה.
- **שיתוף**: מנהל המערכת יכול לשתף פרויקט עם איש צוות. הוא יראה בתפריט "פרויקטים" רק את מה ששותף איתו, ויוכל לעדכן אותו – בלי למחוק ובלי לשנות את השיתוף.

## ספרים

בתפריט **ספרים** (מנהל, רכז הרכזים, צוות):
- **חלוקה למוסדות**: לכל ספר – כמה עותקים חולקו ולכמה מוסדות. "+ חלוקה" רושמת ספר, תאריך, כמות וסטטוס (מתוכנן / נשלח / התקבל) לכמה מוסדות בבת אחת. בוחרים ספר ומסמנים **"הצגת המוסדות שעוד לא קיבלו"** – ואפשר לרשום להם חלוקה בלחיצה.
- **מוסדות**: בתי כנסת, ישיבות וכו' – שם, יישוב, כתובת, איש קשר (גבאי), טלפון, ומה קיבלו. ייבוא מאקסל.
- **הזמנות מהחנות**: כל הזמנה מ-`shop.html` – ממתינה לתשלום ← שולמה ← נשלחה. הזמנה ששולמה נרשמת אצל המזמין ב-CRM כ"רכישת ספרים".
- **קטלוג וחנות**: שם, מחיר, תיאור, תמונה (קישור), "למכירה", וקישור לדף התשלום ב-Jgive (כללי, או ייעודי לספר).
- **Jgive** (מנהל מערכת): הכתובת שמדביקים ב-Jgive, ורשימת העדכונים שהתקבלו.

## חיבור ל-Jgive (אוטומטי)

כל תרומה או תשלום ב-Jgive נכנסים למערכת לבד: איש הקשר נוצר או מתעדכן, נרשמת אצלו "תרומה", ותשלום על הזמנה מהחנות (אותו מייל ואותו סכום) מסמן את ההזמנה "שולמה".
1. ב-Apps Script (בפרויקט של הסקריפט): **Deploy ← New deployment** ← ⚙️ **Web app** ← Execute as: **Me** ← Who has access: **Anyone** ← Deploy ← Authorize.
2. מריצים שוב את **setup**.
3. במערכת: **ספרים ← Jgive** – מעתיקים את הכתובת.
4. ב-Jgive: אזור הארגון ← **Account Settings** ← **Integrations** ← **Webhook URL** ← מדביקים ← Save.

בחנות: המזמין מועבר לדף התשלום ב-Jgive ומתבקש להזין את אותו סכום ואותה כתובת מייל. Jgive לא מאפשר למלא את הסכום מראש מהאתר, לכן אם הסכום או המייל שונים – מסמנים את ההזמנה "שולמה" ידנית.

## בדיקת הרשאות

אחרי כל עדכון של `firestore.rules`: אדם אחד מכל תפקיד נכנס למערכת ולוחץ בתחתית הדף **"בדיקת הרשאות" ← "הרצת הבדיקה"**. המערכת מנסה לקרוא ולכתוב באוספים השונים ומשווה למה שמותר לתפקיד. שורה אדומה = יש בעיה בחוקים (לצלם ולשלוח). הבדיקה לא משנה מידע אמיתי.

## שליחת מיילים, תזכורות, התראות וגיבוי – הסקריפט של המכון

כל המיילים מהמערכת (תשובה לשואל, אישור הרשמה, הודעות, תזכורות) נכנסים לתור, ו**סקריפט שרץ בחשבון ה-Gmail של המכון** שולח אותם תוך כמה דקות – אף אחד לא צריך להתחבר ל-Gmail. כל מייל מופיע ב"דואר שנשלח" של המכון. אותו סקריפט גם: שולח תזכורות לפני מפגשים, בקשות משוב, התראות שו"ת לרבנים, מגבה את הנתונים כל שבוע, ומקבל עדכונים מ-Jgive.

**הסרה מרשימת התפוצה:** בתחתית כל מייל יש קישור "להסרה מרשימת התפוצה". מי שלוחץ – הכרטיס שלו מתעדכן ל"ביקש הסרה", והמערכת והסקריפט לא שולחים אליו יותר מיילים (בחלון השליחה מופיע "X הסירו את עצמם – לא יקבלו"). אם אותו אדם שואל שאלה או נרשם להשתלמות ומסמן מחדש הסכמה – ההסרה מתבטלת. התראות פנימיות לצוות (שאלה חדשה, חסר קישור זום) נשלחות בלי קישור הסרה.

**שליחה לקבוצה:** בכל שליחה ליותר מנמען אחד מסומנת כברירת מחדל האפשרות "לשלוח רק למי שאישר קבלת דיוור".

**התקנה (פעם אחת, כ-10 דקות):**
1. **הרשאה לחשבון המכון**: ב-Firebase, עם החשבון שפתח את הפרויקט: ⚙️ Project settings ← **Users and permissions** ← **Add member** ← כתובת ה-Gmail של המכון ← תפקיד **Editor** ← Add. אם חשבון המכון הוא שפתח את הפרויקט – מדלגים.
2. מתחברים ל-**script.google.com** עם חשבון ה-Gmail של המכון ← **New project** ← נותנים שם: "הסקריפט של משפטי ארץ". (אם כבר התקנתם את "מתזמן מיילים" – פותחים אותו.)
3. ⚙️ **Project Settings** (בתפריט הצד) ← מסמנים **Show "appsscript.json" manifest file in editor**.
4. חוזרים ל-**Editor**: בקובץ `Code.gs` מוחקים הכול ומדביקים את תוכן `mail-scheduler.gs`. בקובץ `appsscript.json` מוחקים הכול ומדביקים את תוכן `appsscript.json` מהתיקייה ← שמירה (Ctrl+S).
5. בסרגל העליון בוחרים את הפונקציה **setup** ← **Run** ← Review permissions ← בוחרים את חשבון המכון ← Advanced ← Go to... ← **Allow**.
6. במערכת: **הגדרות ← שליחת מיילים** צריך להופיע "סקריפט השליחה פעיל". לוחצים "שליחת מייל ניסיון לעצמי" – המייל יגיע תוך כמה דקות.
7. לחיבור ל-Jgive – פרק "חיבור ל-Jgive".

**בכל עדכון של הסקריפט** (כמו בגרסה הזו): מדביקים מחדש את שני הקבצים, שומרים, ומריצים שוב **setup**. Google יבקש לאשר הרשאה חדשה (Google Drive – לגיבוי). אם פרסמתם Web App ל-Jgive: Deploy ← Manage deployments ← ✏️ ← Version: **New version** ← Deploy.

**אם במסך מופיעה שגיאה** כמו "API has not been used in project": ב-Firebase ← Project settings מעתיקים את **Project number**. ב-Apps Script ← Project Settings ← **Google Cloud Platform (GCP) Project** ← Change project ← מדביקים ← Set project, ומריצים שוב את **setup**. אם הגיבוי נכשל עם שגיאה דומה על Drive – באותו פרויקט ב-console.cloud.google.com ← APIs & Services ← Library ← **Google Drive API** ← Enable.

**מגבלות:** חשבון Gmail רגיל שולח עד כ-500 מיילים ביום. כל נמען מקבל מייל נפרד, ולכן הכתובות לא נחשפות לאחרים. לדיוור שיווקי רחב (אלפי נמענים) עדיף שירות דיוור ייעודי.

## הערות

- התוכנית החינמית של Firebase (Spark) מספיקה – כולל החיבור ל-Jgive (דרך הסקריפט) והגיבוי.
- העלאת קבצים ישירות למערכת (חומרי לימוד, תמונות ספרים) דורשת את Firebase Storage, שזמין רק בתוכנית בתשלום. לכן מדביקים קישורים (Google Drive).
- לא נדרשים אינדקסים מיוחדים ב-Firestore.
