# מערכת מכון משפטי ארץ

ניהול קשרים (CRM), שו"ת, השתלמויות ומעקב מחקר – באתר אחד על GitHub Pages, עם מסד נתונים ב-Firebase.

## הדפים באתר

| קובץ | למי | מה זה |
| --- | --- | --- |
| `index.html` | צוות | מערכת הניהול (כניסה עם Google, רק לכתובות מורשות) |
| `ask.html` | ציבור | טופס "שאל את הרב" |
| `shut.html` | ציבור | מאגר שו"ת (שאלות שפורסמו בעילום שם) |
| `course.html?c=...` | ציבור | דף נחיתה והרשמה להשתלמות – טופס פתוח, בלי חשבון (הקישור בלשונית "פרסום") |
| `my.html` | משתלמים מאושרים | האזור האישי (כניסה עם Google של המייל שנרשמו איתו): לו"ז, זום, הקלטות, נוכחות, רקע |
| `accessibility.html`, `privacy.html` | ציבור | הצהרת נגישות ומדיניות פרטיות (להשלים את המסומן בצהוב) |
| `js/config.js` | – | פרטי Firebase, קטגוריות ברירת מחדל, הגדרות שליחת מיילים |
| `firestore.rules` | – | חוקי אבטחה – **להדביק ב-Firebase אחרי כל עדכון שלהם** |
| `mail-scheduler.gs`, `appsscript.json` | – | סקריפט המתזמן למיילים מתוזמנים (מדביקים ב-Apps Script, לא צריך להעלות לאתר) |

## הקמה (פעם אחת)

1. **פרויקט Firebase**: console.firebase.google.com ← Add project.
2. **מסד נתונים**: Build ← Firestore Database ← Create database ← Production mode ← מיקום `eur3`.
3. **חוקי אבטחה**: לשונית Rules ← מדביקים את כל `firestore.rules` ← Publish.
4. **כניסה עם Google**: Build ← Authentication ← Sign-in method ← Google ← Enable ← Save.
5. **חיבור האתר**: Project settings ← Your apps ← `</>` ← מעתיקים את `firebaseConfig` ל-`js/config.js`.
6. **GitHub Pages**: Settings ← Pages ← Branch: main ← Save.
7. **דומיין מורשה**: Authentication ← Settings ← Authorized domains ← מוסיפים `שם-המשתמש.github.io`.
8. **מנהל ראשון**: Firestore ← Start collection `allowedEmails` ← Document ID = כתובת ה-Gmail שלך באותיות קטנות ← שדה `role` = `admin`, שדה `name` = השם שלך.
9. מכאן מוסיפים את כל הצוות מתוך האתר, בלשונית **משתמשים**.

## תפקידים

| תפקיד | מה רואה ועושה |
| --- | --- |
| מנהל מערכת (`admin`) | הכול, כולל משתמשים, הגדרות ומחיקות |
| רכז הרכזים (`head`) | הכול חוץ מניהול משתמשים: CRM, שו"ת, כל ההשתלמויות, מעקב מחקר, הגדרות |
| צוות (`staff`) | CRM, שו"ת, ייבוא, כל ההשתלמויות |
| רב משיב (`rabbi`) | שו"ת ותקציר על השואל |
| רכז השתלמות (`course_manager`) | רק ההשתלמויות שהוא רשום כרכז שלהן (פרטים, לו"ז, נרשמים, נוכחות, הקלטות, פרסום) + לוח השנה של כולן |
| רכז מחקר (`research_coord`) | הדיווחים החודשיים של כל החוקרים (גם מנהל ורכז הרכזים רואים אותם) |
| חוקר (`researcher`) | רק הדיווח החודשי שלו |

**משתלמים** לא צריכים להיות ברשימת המשתמשים. הם נרשמים בטופס הפתוח, הרכז מאשר, ואז הם נכנסים ל-`my.html` עם חשבון Google של כתובת המייל שאיתה נרשמו. כל אחד רואה רק את ההשתלמויות שאושר אליהן.

## השתלמויות – איך עובדים

**השתלמויות ← + השתלמות חדשה** פותח אשף בשישה צעדים. בכל צעד יש "הקודם / הבא", וצעד שהושלם מסומן ב-✓:
1. **פרטים**: שם, תיאור, מרצים, תאריכים, רכזים, מלגות והקלטות.
2. **לו"ז**: מפגש בודד או סדרה שבועית, עם התראה על התנגשות (אותו מרצה או אותו חשבון זום באותו זמן, בכל ההשתלמויות).
3. **דף ההרשמה**: תצוגה מקדימה חיה של הדף כפי שהנרשמים יראו אותו. בתצוגה המקדימה ההרשמה לא נשלחת.
4. **מודעה**: נבנית מתבנית הפלאייר של המכון ומתמלאת אוטומטית: שם ההשתלמות, מספר המפגשים, ימים ושעות, תאריכים (עבריים ולועזיים), רשימת הנושאים והמרצים מהלו"ז, טקסט המלגה, וקוד QR שמוביל לדף ההרשמה. ב**עורך** אפשר לשנות כל טקסט, לגרור, להגדיל ולהקטין כל אלמנט, להחליף צבעים, גופנים ותמונות. אלמנט שמסומן "להציג רק אם יש ערך" (למשל תיבת המלגה) נעלם כשאין לו תוכן. "שמירה" שומרת להשתלמות הזו. מנהל ורכז הרכזים יכולים גם לשמור **כתבנית לכל ההשתלמויות**. "חזרה לעיצוב המקורי של המכון" מחזיר לפלאייר המקורי.
5. **רקעי זום**: רקע לכל מרצה מתבנית רקע הזום של המכון. מתחלפים רק שם המרצה ונושא ההרצאה (הנושא של המפגשים שלו בלו"ז, ואם אין – שם ההשתלמות). אפשר להוריד רקע לכל מרצה, או את כולם בלחיצה אחת. גם המשתלמים מורידים רקע עם השם שלהם מהאזור האישי.
6. **פרסום**: כפתור "פתיחת ההרשמה", קישור לדף ההרשמה והודעה מוכנה לוואטסאפ.

אחרי הפרסום עובדים בלשוניות **ניהול**:
- **נרשמים**: ממתינים, מאושרים, נדחו וביטלו. אישור נותן גישה לאזור האישי ומציע לשלוח מייל אישור. אפשר גם הוספה ידנית, עריכה, אישור מלגות, ייצוא, "מייל למאושרים" ו"תזכורת למפגש הבא".
- **נוכחות**: סימון ידני או ייבוא דוח משתתפים מזום.
- **הקלטות**: קישורי יוטיוב לכל מפגש, וכפתור שמציג או מסתיר אותם מהמשתלמים.

**לוח שנה**: כל המפגשים מכל ההשתלמויות, עם רשימת התנגשויות לכל חודש. רשימת חשבונות הזום מוגדרת ב**הגדרות**.

## מחקר – דיווח חודשי

- **חוקר**: פעם בחודש כותב **מה עשה והשיג החודש** ו**מה היעד שלו לחודש הבא**. מעל הטופס מוצג היעד שהציב לעצמו בחודש הקודם, כך שבסוף כל חודש הוא רואה מה רצה להשיג מול מה שהשיג. מתחת – כל החודשים הקודמים שלו. בשבוע הראשון של החודש הטופס נפתח אוטומטית על החודש שהסתיים.
- **מנהל, רכז הרכזים ורכז מחקר**: מסך אחד לכל חודש, כל החוקרים זה מתחת לזה: היעד שהציב, מה הושג, והיעד לחודש הבא. למעלה – כמה הגישו ומי עוד לא. אפשר לכתוב הערה לכל חוקר (הוא רואה אותה), לדפדף בין חודשים ולהדפיס או לשמור כ-PDF.

## שאר המערכת

- **ייבוא**: Excel או CSV (גם בקידוד של Excel בעברית). אנשים קיימים מזוהים לפי מייל או טלפון.
- **חיתוכים**: באנשי קשר, "תנאי היסטוריה" ← שמירה כרשימה ← ייצוא או העתקת מיילים (רק של מאשרי דיוור).
- **שו"ת**: קטגוריות ותגיות אוטומטיות לפי מילות מפתח מוגדרות ב**הגדרות**.

## שליחת מיילים מחשבון ה-Gmail של המכון

המערכת שולחת מיילים (תשובה לשואל, אישור הרשמה, הודעה לנרשמים, תזכורת) **מכתובת ה-Gmail של המכון**, וכל מייל מופיע שם בתיקיית "דואר שנשלח". מי ששולח מתחבר לחשבון המכון בחלון של Google, פעם בשעה בערך. לכן צריך לדעת את הסיסמה של החשבון, או שהחשבון יהיה מחובר בדפדפן.

**הגדרה (פעם אחת, כ-15 דקות)**, ב-console.cloud.google.com, בפרויקט של Firebase (בוחרים אותו למעלה):
1. **APIs & Services ← Library** ← מחפשים **Gmail API** ← **Enable**.
2. **Google Auth Platform** (או OAuth consent screen) ← Get started: שם האפליקציה "משפטי ארץ", מייל תמיכה, **Audience: External** ← Create.
3. **Audience ← Test users ← Add users** ← מוסיפים את כתובת ה-Gmail של המכון.
4. **Data access ← Add or remove scopes** ← מסמנים `.../auth/gmail.send` ← Update ← Save.
5. **Clients ← Create client** ← Web application ← **Authorized JavaScript origins**: `https://aryeminkov-maker.github.io` ← Create ← מעתיקים את ה-**Client ID**.
6. ב-`js/config.js` ממלאים את `MAIL_FROM` (כתובת ה-Gmail של המכון) ואת `MAIL_CLIENT_ID`, ומעלים ל-GitHub.
7. במערכת: **הגדרות ← שליחת מייל ניסיון לעצמי**.

בהתחברות הראשונה Google יציג "Google hasn't verified this app". זה תקין לאפליקציה פנימית: לוחצים Continue ומסמנים את ההרשאה לשליחת מיילים.

**מגבלות:** חשבון Gmail רגיל שולח עד כ-500 מיילים ביום. כל נמען מקבל מייל נפרד, ולכן הכתובות לא נחשפות לאחרים. לדיוור שיווקי רחב (עדכונים, בקשות תרומה) עדיף שירות דיוור ייעודי עם קישור הסרה.

## מיילים מתוזמנים

בכל חלון שליחה אפשר לבחור **"לתזמן ל:"** תאריך ושעה. מיילים מתוזמנים נשלחים על ידי סקריפט קטן שרץ בחשבון ה-Gmail של המכון ובודק כל 5 דקות אם הגיע זמנם, גם כשאף מחשב לא פתוח. במסך **מיילים** רואים מה מתוזמן, מבטלים, ובודקים שהמתזמן פעיל.

**שליחה לקבוצה:** בכל שליחה ליותר מנמען אחד מסומנת כברירת מחדל האפשרות "לשלוח רק למי שאישר קבלת דיוור". אנשי קשר שביקשו הסרה לא מקבלים מיילים בכלל.

**התקנת המתזמן (פעם אחת, כ-10 דקות):**
1. **הרשאה לחשבון המכון**: ב-Firebase, עם החשבון שפתח את הפרויקט: ⚙️ Project settings ← **Users and permissions** ← **Add member** ← כתובת ה-Gmail של המכון ← תפקיד **Editor** ← Add. אם חשבון המכון הוא שפתח את הפרויקט – מדלגים.
2. מתחברים ל-**script.google.com** עם חשבון ה-Gmail של המכון ← **New project** ← נותנים שם: "מתזמן מיילים".
3. ⚙️ **Project Settings** (בתפריט הצד) ← מסמנים **Show "appsscript.json" manifest file in editor**.
4. חוזרים ל-**Editor**: בקובץ `Code.gs` מוחקים הכול ומדביקים את תוכן `mail-scheduler.gs`. בקובץ `appsscript.json` מוחקים הכול ומדביקים את תוכן `appsscript.json` מהתיקייה ← שמירה (Ctrl+S).
5. בסרגל העליון בוחרים את הפונקציה **setup** ← **Run** ← Review permissions ← בוחרים את חשבון המכון ← Advanced ← Go to... ← **Allow**.
6. במערכת, במסך **מיילים**, צריך להופיע "המתזמן פעיל".

**אם במסך מופיעה שגיאה** כמו "API has not been used in project": ב-Firebase ← Project settings מעתיקים את **Project number**. ב-Apps Script ← Project Settings ← **Google Cloud Platform (GCP) Project** ← Change project ← מדביקים ← Set project, ומריצים שוב את **setup**.
